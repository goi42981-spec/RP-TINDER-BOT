# RP Tinder Bot

Telegram-бот для РП-проекта. Принимает анкету у пользователя через кнопки и сохраняет для последующего матчинга.

## Возможности

- Проверяет, состоит ли пользователь в указанном РП-чате (`REQUIRED_CHAT_ID`). Если нет — просит вступить.
- Запускает анкету через `/start` → кнопка «Заполнить анкету».
- 4 шага анкеты:
  1. Пол персонажа: **Ж / М / Другое** (inline-кнопки)
  2. Предпочитаемый пол: **Ж / М / Другое** (inline-кнопки)
  3. Юзернейм (текст; парсится в формат `@nickname`)
  4. Ссылка на анкету (валидация: должен быть URL с `http(s)://`; если прислали текст анкеты вместо ссылки, бот просит ссылку ещё раз)
- Сохраняет/обновляет анкету в PostgreSQL (Neon) или SQLite.
- `/me` — показывает твою текущую анкету.
- `/find` — поиск пары (свайпы ❤️ / 👎).
- `/likes` — входящие лайки.
- `/cancel` — отменить заполнение.
- **Постоянное хранилище:** PostgreSQL (`DATABASE_URL`) для продакшена или SQLite-файл для локальной разработки.

## Команды администратора

Доступны только пользователям из `ADMIN_IDS` (по умолчанию — владелец и запасной аккаунт; можно переопределить через переменную окружения `ADMIN_IDS`, ID через запятую).

- `/all` (алиасы: `/list`, `/anketi`) — показывает **все анкеты** списком: ID, пол персонажа, кого ищет, юзернейм, ссылку и статус (забанен/нет). Под каждой анкетой — кнопка 🚫 Забанить / ✅ Разбанить.
- `/ban <ID|@ник> [причина]` — забанить пользователя. Забаненные пропадают из поиска и входящих лайков у всех и не могут пользоваться ботом.
- `/unban <ID|@ник>` — снять бан.
- **Бан по пересланному сообщению:** перешли боту сообщение тролля — бот покажет карточку с кнопкой 🚫 Забанить (банит **оригинальный аккаунт** автора). Либо ответь `/ban` на пересланное сообщение.

> ⚠️ Если автор включил в Telegram «запрет ссылки на аккаунт при пересылке», его оригинальный ID не передаётся — тогда бан по форварду невозможен, нужно банить по ID/@юзернейму.

Админов забанить нельзя.

## Запуск локально

1. Python 3.10+
2. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создать бота у [@BotFather](https://t.me/BotFather), получить токен.
4. Узнать `chat_id` РП-чата (см. `.env.example`).
5. Скопировать `.env.example` → `.env` и заполнить:
   ```bash
   cp .env.example .env
   ```
6. Запустить (polling-режим для разработки):
   ```bash
   python bot.py
   ```

## Деплой на Render.com (бесплатный 24/7 с UptimeRobot и Neon Postgres)

Проект содержит готовый `render.yaml` (Blueprint) и `Dockerfile`.

1. Создайте бесплатную базу на [Neon](https://neon.tech) (Sign in with GitHub):
   - **New Project** → Postgres 16, любой регион.
   - На странице проекта откройте **Connection Details** → скопируйте строку **Pooled connection** (`postgresql://...?sslmode=require`).
2. Зарегистрируйтесь на https://render.com — без карты, через GitHub или email.
3. **New** → **Blueprint** → подключите этот репозиторий.
4. В настройках сервиса задайте секреты:
   - `BOT_TOKEN` — токен от @BotFather.
   - `DATABASE_URL` — строка подключения Neon (включая `?sslmode=require`).
   - `REQUIRED_CHAT_ID` — ID вашего РП-чата (например, `-1001234567890`).
5. Дождитесь деплоя. Health-check на `/healthz` должен стать зелёным.
6. Чтобы сервис не засыпал (free-tier Render засыпает через 15 минут простоя):
   - Зарегистрируйтесь на https://uptimerobot.com (бесплатно).
   - **Add new monitor** → HTTP(S) → URL: `https://<имя-сервиса>.onrender.com/healthz` → интервал 5 минут.

Вся база хранится в Neon — данные переживают любые перезапуски и редеплои Render.

Если `DATABASE_URL` не задан, бот использует локальный SQLite (`DB_PATH`), который на бесплатном тарифе Render обнуляется при каждом редеплое — используйте только для тестов.

## Docker (свой VPS)

```bash
docker build -t rp-tinder-bot .

docker run -d \
    --name rp-tinder-bot \
    -e BOT_TOKEN=YOUR_TOKEN \
    -e REQUIRED_CHAT_ID=-1001234567890 \
    -e DATABASE_URL=postgresql://user:pass@host/db?sslmode=require \
    --restart unless-stopped \
    rp-tinder-bot
```
